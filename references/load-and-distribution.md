# 周负荷、热量与强度分布

## 首次排周计划必须确认

提取已知信息后，集中询问：

> 这周希望多少骑行TSS，是目标范围还是硬上限？最近4–6周实际周TSS、时长和恢复如何？偏好极化（希望PI>2）、金字塔还是按目标推荐？有没有实测LT1/LT2或当前采用的分区？哪些课希望在坡上完成？

不知道TSS或阈值时可以给带假设的初稿，不要求用户先买设备/测试。记录目标、容许浮动、统计口径及未知项；周TSS不能脱离小时预算和训练史。计划有冲突时说明原因和可选取舍，不通过加课追数字。力量、热暴露和局部肌肉疲劳单独备注，不伪换算为骑行TSS。

## 单课与周汇总输出

每节课给：目的、地形、总时长、强度、估算TSS、机械做功kJ、粗略代谢kcal、补给重点和估算方法。周汇总给小时/TSS范围、与目标的差额、三强度区时间分布/PI（可算时）、休息日和可删课顺序。热量是骑行消耗估计，不是全天总消耗或必须吃回的热量。

- `work_kJ = Σ(W × seconds) / 1000`。
- 假设总机械效率20–25%时，`kcal ≈ work_kJ / (4.184 × efficiency)`；因此给约0.96–1.20倍机械kJ的粗略范围，不写成精确1:1，也不把NP乘时长当做功。
- `IF = NP / FTP`，`TSS ≈ hours × IF² × 100`。NP由30秒移动平均功率的四次方均值开四次方估计；**平均功率/FTP不能代替变功率课的IF**。
- 计划阶段可将目标分段展开为1秒恒定功率序列估算NP/TSS；区间取中点并说明，可另算全低/全高情景。实际滑行、峰值、热负荷、分区和FTP误差使结果变化，短冲刺的局部负担也不能仅靠TSS解释。
- 无FTP/功率且无法建立可解释估计时，TSS/kJ/kcal填“数据不足，待估”，同时给RPE与分钟；不为每栏硬造一个数字。只知道“sprint”时先确认功率或使用明确标注的情景范围。
- 周TSS是各节课TSS之和；不能对整周跨休息日的拼接功率曲线算一个NP后替代逐课相加。反馈后同时显示原计划、实际已完成和修订后剩余周TSS。

可用标准库工具：

```powershell
python -X utf8 scripts/plan_metrics.py --workout examples/z2-climbing.txt --ftp 250
python -X utf8 scripts/plan_metrics.py --zone-minutes 648 24 48
python -X utf8 scripts/plan_metrics.py --week examples/polarized-week.json
```

支持 `- 10m 65%`、`- 45s 125-130%`、平铺的 `Nx` 循环；循环空行结束，恢复若在循环内就会每次重复，包括最后一次。爬坡要求写在段标题。斜坡功率、任意文字步骤、未定峰值冲刺与嵌套循环需先显式展开成支持的常数/范围步骤，不让解析器悄悄忽略。`--range-scenarios`额外算全低/全高情景；`--lt1-pct`、`--lt2-pct`只在用户提供或明确接受的阈值情景下使用。该工具不是活动文件读取器。生成器、导出与 MCP 现共用相同的展开步骤及计算模块；CLI 本身不写日历。多周时间/负荷冲突用 `scripts/training_plan.py validate` 校验，格式见 [实现说明](../docs/IMPLEMENTATION.md#5-portable-profiles-and-feasibility)。

## PI与极化 / 金字塔

PI用**三生理强度区**：低区在LT1/VT1及以下，中区在两阈值之间，高区在LT2/VT2以上。不要把常见功率Z1恢复、Z2耐力、Z3节奏直接传入PI；常规Z2爬坡通常属于这里的低区，前提是确实在个人LT1以下。

令 `p_low + p_mid + p_high = 1`，输入是同口径时间占比：

```text
PI = log10((p_low / p_mid) × p_high × 100)
```

- 采用用户要求的 `PI > 2` 极化判据，同时检查低区占主导、高区多于中区。金字塔为低区 > 中区 > 高区；不是所有PI≤2的分布都叫金字塔。
- 例：12小时中低/中/高=648/24/48min，即90%/3.33%/6.67%，PI≈2.255，满足上述极化结构。**直接把90、3.33、6.67当分数代入会算错**。
- 某区为0时PI不作有限数报告，不擅加epsilon或用“无穷大”证明训练优秀；纯低强度恢复周也不必追PI。没有个体阈值则说明未知，或给用户接受的代理阈值情景，不声称测得生理PI。
- 同时记录time-in-zone与按主要刺激分类的质量课次数；不能把“6节课2节质量课”当作33%高区时间。短微间歇的恢复是否逐秒计入低区也会影响PI，前后统计方法必须一致。
- 默认以本周和滚动3–4周看分布，不通过一次额外高强度课去修饰PI；不要将20%训练小时都处方成真实>LT2时间。

## 不同时长的模式选择

- **每周>10h**：依用户偏好更主动推荐以极化为候选，把新增时间主要放在低区耐力（可含Z2坡），集中1–2次质量日，避免大量附加甜区。>10h是本Skill的排课偏好，不是研究证明的生理分界；仍尊重比赛专项期、恢复和用户选择。
- **≤10h或FTP/长坡专项期**：极化和金字塔均可讨论，金字塔可保留适量Tempo/阈值；不能因时间少就把每次课都变高强度。
- 用户明确选金字塔时按该模式规划；更高PI不代表更好的个体适应。先看完成率、恢复、目标进展和负荷耐受，再看分布数字。

## Z2也要有地形任务

爬坡目标者的部分低强度耐力课明确写“**在可控缓坡完成**”，给坡上有效分钟、功率/心率上限、RPE、坐姿/变速提示和下坡恢复。路线可先找可连续10–20分钟的缓坡；具体坡度取决于最低齿比与能力，不强制统一坡度/低踏频。保持个人低区，不因上坡追速度、过顶冲刺或提高功率上限。

示例：90分钟，15min热身 +20min缓坡65% FTP +5min安全下坡/平路轻松 +20min缓坡65% +20min轻松耐力60% +10min冷身。FTP250W时机械做功约806.3kJ；用工具估算TSS和热量。若齿比无法守住低区，换更缓路线或骑行台坡度模拟，不把被迫踩进中区仍报为Z2。

在坡上练的是目标地形中的配速、骑姿、变速与持续完成能力，不声称相同功率的上坡必然比平路产生更多有氧适应。无安全坡路时提供骑行台替代并说明户外技术练习的缺口。
